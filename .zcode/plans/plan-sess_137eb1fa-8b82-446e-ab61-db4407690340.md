## 2. Kalan hafıza (free RAM) algılama çalışacak

Sunucu tarafında Termux'un `/proc/meminfo` dosyasını okuyan yeni bir API uç noktası eklenecek. Bu, mevcut `/api/battery` mimarisiyle birebir uyumlu.

**`server.mjs` değişikliği:**
- `case '/api/memory':` dalı eklenecek.
- `run('cat', ['/proc/meminfo'])` çağrısı ile 4 satır okunacak: `MemTotal`, `MemFree`, `Buffers`, `Cached` (kB cinsinden).
- `free = MemFree + Buffers + Cached` (Linux'ta "available" yaklaşımı) hesaplanıp MB'a çevrilecek.
- JSON: `{ total: <MB>, free: <MB>, used: <MB> }`. Okunamazsa `{ ok: false }`.

**Client tarafı:**
- `src/lib/termux.ts` — `memory(): Promise<MemoryInfo | null>` metodu eklenecek.
- `src/lib/types.ts` veya `termux.ts` içinde `MemoryInfo` tipi tanımlanacak.
- `src/pages/Dashboard.tsx` "Cihaz" bölümünde (satır 247-271) batarya ring'inin yanına küçük bir RAM göstergesi eklenecek: `boş / toplam` formatında, örn. "1.2 / 3.5 GB". `termuxUp === false` ise gizlenecek (mevcut davranışla tutarlı).

## 3. APK build sonrası dashboard köküne kopyalansın

**`scripts/build-apk.sh` güncellenecek:**

Mevcut `./gradlew assembleDebug` başarıyla bitince, build çıktısı (`android/app/build/outputs/apk/debug/app-debug.apk`) proje kökündeki `Aurora.apk` dosyasına kopyalanacak. Üzerine yazma (`cp -f`) kullanılacak.

```
./gradlew assembleDebug

APK_SRC="android/app/build/outputs/apk/debug/app-debug.apk"
if [ -f "$APK_SRC" ]; then
  cp -f "$APK_SRC" Aurora.apk
  echo "✓ APK dashboard köküne kopyalandı: Aurora.apk"
fi

echo
echo "✓ APK hazır:"
echo "    - android/app/build/outputs/apk/debug/app-debug.apk"
echo "    - Aurora.apk  (proje kökü)"
```

`package.json`'daki `apk` scripti aynı kalacak (`npm run apk` zaten `bash scripts/build-apk.sh`'i çağırıyor).

## 4. shadcn/ui entegrasyonu (minimum kapsam)

Mevcut özel UI tamamen korunacak. shadcn yalnızca **altyapı + yeni bileşenler** için kurulacak.

**Adımlar:**

1. **Bağımlılıklar:** `package.json`'a `clsx` ve `tailwind-merge` eklenecek (shadcn'in zorunlu helper'ları).
2. **`src/lib/utils.ts` güncellenecek:** Canonical `cn` helper'ı eklenecek (mevcut `cx` korunacak — geriye uyumluluk):
   ```ts
   import { clsx, type ClassValue } from 'clsx';
   import { twMerge } from 'tailwind-merge';
   export function cn(...inputs: ClassValue[]) { return twMerge(clsx(inputs)); }
   ```
3. **`components.json` oluşturulacak:** shadcn CLI için config (TypeScript, Tailwind v4 uyumlu yollar, neutral baseColor).
4. **İlk shadcn bileşenleri kurulacak** (`npx shadcn@latest add` ile):
   - `button` — yeni varyant gerektiğinde kullanılacak
   - `dialog` — `src/components/Dialog.tsx` (özel implementasyon) **korunacak**, çünkü zaten çalışıyor ve tüm sayfalar onu kullanıyor; shadcn Dialog kurulacak ama **opsiyonel olarak** ileride Dialog.tsx'i ona taşımak için referans olarak hazır olacak.
   - `switch` — `Settings.tsx`'teki 6 özel `Toggle`'ın yerini alacak (en yüksek görsel kazanım burada).
   - `alert-dialog` — `Notes.tsx:84` ve `Settings.tsx:401`'deki `window.confirm` çağrılarını süsleyecek.
   - `tabs` — `Schedule.tsx:64-87`'deki özel gün sekmesini alacak.
   - `input`, `textarea` — form inputları standardize edilecek.
   - `select` — mevcut native `<select>`'leri (Schedule, Settings, Todos, Student) süsleyecek.

5. **Geçiş stratejisi — kademeli:**
   - Önce `cn` helper'ı ve `button` kurulacak; mevcut `btn` utility'si `@utility` olarak kalacak.
   - `switch` ilk hedef: `Settings.tsx`'teki `Toggle` bileşeni shadcn `<Switch>` ile değiştirilecek (6 kullanım). Bu tek başına UI'da somut bir güzelleşme sağlar.
   - `alert-dialog`: `confirm()` kullanan 2 yer shadcn dialog'a taşınacak.
   - Geri kalan primitive'ler shadcn olarak kurulacak ama mevcut sayfalar bu PR'da zorunlu olarak taşınmayacak — `btn btn-primary` yerine `<Button variant="primary">` opsiyonel kalacak. Kullanıcı isterse ileride tüm UI'ı shadcn'e geçirebiliriz (ayrı bir PR).

**Tasarım uyumu:** shadcn'in `src/index.css` zaten CSS değişkenleri (--paper, --ink, --accent…) ile çalışıyor. shadcn bileşenleri bu değişkenlere otomatik olarak uyum sağlayacak şekilde `components.json`'da `cssVariables` ile ayarlanacak. Özel Notion paleti bozulmayacak.
